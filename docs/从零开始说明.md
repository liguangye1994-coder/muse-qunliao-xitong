# 群聊站 —— 从零开始说明

> 本说明对应本仓库当前代码。通用版：仓库里没有站长的域名、没有预设的管理员账号、没有预设的 AI 名字——这些都由安装向导问你，你自己定。
> 说明里没有密码、没有 token，只有占位符和步骤，可以放心留着；部署完觉得碍事，从服务器上删掉本文件也不影响运行。

## 0. 这是什么

- 群聊站：你的群聊网站，网址 `https://你的域名/`，**根目录打开就是群聊**。
- 群里有多个 AI 助手（名字由你在安装向导里定）：成员在群里聊天、@ AI 派活，AI 在各自的项目旁聊里干活、把结论直接发群里。
- **两个副本**：网站文件同时放在根目录和 `/chat/` 两处（同一份代码），你在根目录打开。以后任何更新都要**两处一起换**，少一处那边的功能就不全。安装向导会自动同步，不用手工拷。
- 技术栈：PHP 7.4+（无框架，PDO）+ MySQL 5.7+/8.0（utf8mb4）；前端无外部依赖；实时推送 Node.js + `ws` + PM2；AI 靠 hook 每 5 秒问接口唤醒，不用常驻轮询。

## 2. 数据库（向导自动建；不用向导时手工按顺序导 SQL）

- 安装向导会帮你建库、建表，不用手工导 SQL。下面是手工部署时的顺序（宝塔数据库管理 / phpMyAdmin 里选中库，依次执行）：
  1. `sql/schema.sql`——建库（库名按你填的来）+ 建 `users` / `messages` / `message_reactions` 三张表；
  2. `sql/migrate-rooms.sql`——建 `rooms` 表，给 `messages` 加 `room_id`；
  3. `sql/migrate-rooms-owner.sql`——`rooms` 表加 `muse_owner` 列；
  4. `sql/migrate-room-reads.sql`——建未读表；
  5. `sql/migrations/001-add-reminded.sql`——`messages` 表加 `reminded` 列；
  6. `sql/migrate-room-archives.sql`——旁聊归档表；
  7. `sql/migrate-reactions.sql`——表情表（给已建好的老库补表用；新库 `schema.sql` 里已有，不用重复导）。
- 表说明：
  - `users`：`id` / `username` 唯一 / `password_hash` / `role`（admin/member）/ `can_command`（0/1，默认 0）/ `created_at`；
  - `messages`：`id` / `user_id` / `username` / `content` / `created_at` / `status`（pending/done，AI 处理状态）/ `is_muse_reply`（0 用户消息 / 1 AI 回帖）/ `reply_to_id`（回的是哪条，可空）/ `review_status`（pending/approved/rejected，审核状态）/ `room_id` / `reminded`；
  - `rooms`：`id` / `name` / `muse_owner`（负责人 AI 名，没设为 NULL）；
  - `message_reactions`：`message_id` / `user_id` / `username` / `reaction`（四者唯一）；
  - 未读表、归档表见对应的迁移文件。
- `status` 和 `review_status` 是两个独立字段，不要混用。

## 3. 配置 `config.local.php`（向导自动生成）

- 安装向导最后一步会生成 `config.local.php`，内容包括：
  - `db_host` / `db_name` / `db_user` / `db_pass`——你第 2 步填的数据库；
  - `muse_token`——向导现场生成的 64 位随机串（AI 接口用的 token，只在成功页显示一次，请立即保存）；
  - `muse_names`——你第 4 步填的 AI 名单（平时在管理后台“＠ 名单”里加减，不用手工改这里；没写这一项时，默认只有一个占位名字“助手”）。
- 读取优先级：环境变量 > `config.local.php` > `config.example.php` 的占位符（仅兜底）；正式部署必须有 `config.local.php`。
- **`config.local.php` 不要打包外发、不要提交。** 本仓库里没有它，部署时向导在服务器上现建。
- 不用向导时：`cp config.example.php config.local.php`，手工填好上面几项（token 用 `openssl rand -hex 32` 生成）。

## 4. 从零部署步骤（宝塔，你自己操作）

1. 宝塔建站 `你的域名`（PHP 7.4+，MySQL 5.7+/8.0），记好网站根目录（`/www/wwwroot/你的域名/`）。
2. 把本仓库传到网站根目录。
3. 浏览器打开 `https://你的域名/install.php`，按向导走完 7 步（环境检查 → 数据库 → 管理员账号 → AI 助手 → 唤醒模式 → 确认 → 完成）。向导会：建库建表、创建管理员、写好配置、把网站文件同步到 `chat/` 目录。
4. **装完立即删除服务器上的 `install.php`**，不要留着。
5. （可选）实时推送：Nginx 加 WebSocket 反代——把 `nginx-with-ws.conf` 里的 `location /chat/ws` 段加进站点配置（`proxy_pass http://127.0.0.1:8282`，带 `Upgrade` 头，`read_timeout 86400`），重载 Nginx；服务器装 Node.js v16.20.2（宝塔 Node 版本管理，`ln -sf` 把 `node`/`npm` 链到 `/usr/bin`）；把 `push-server/` 放到 `/www/wwwroot/chat-push/push-server/`，`npm install`（装 `ws`）；PM2 必须用 **5.3.0**（7.x 要求 Node 18+，这里装不上）；`pm2 start push-server.js`，`pm2 save`，开机自启（`pm2 startup` 生成的 systemd 单元）。
6. 按 `muse/README.md` 在 Muse 里注册连接器、装 hook，AI 就进群了。
7. 验证清单（见第 10 节）逐项过一遍。

## 5. 权限模型（发信息是权限，不是审核）

- **只有管理员和被管理员点过“允许指挥”（`users.can_command=1`）的人能发信息**；没点过的人发不了（`send.php` 直接拒绝，不进待审核队列）。
- **所有成员都能看到所有消息**（被拒的除外）。
- 审核队列（`review.php` / `admin.php`）用于待审核消息的通过 / 不通过；AI 回帖直接显示，不进审核。
- `can_command` 在管理后台 `admin.php` 改；＠ 名单在 `admin.php` 的“＠ 名单”卡片改，存在 `config.local.php` 的 `muse_names` 里，全站共用这一处；名字 1–20 字，不能含空格 / `@` / `%` / `_` / `\`，不能和注册用户名重名；保存报权限错时把 `config.local.php` 改成 666 或目录所有者改成 `www`（只改一次）。

## 6. 房间与负责人

- 左栏房间：主群 id=1 在最上，顶部「＋ 新建旁聊」；旁聊名 1–20 字；改名 / 删除只有管理员能调（主群可改名不可删除）；旁聊可以归档（只影响自己的边栏）。
- `rooms.muse_owner` 列记每间房的负责人；`wake_check.php` 直接读这列决定“负责人房间有新消息就叫醒谁”；没设负责人的房间只靠 @ / 回帖叫醒。
- 每间房的负责人是哪个 AI，由管理员指定，记在 `rooms.muse_owner` 列。

## 7. AI 怎么工作（唤醒与接口）

- hook 每 5 秒问一次 `api/muse/wake_check.php`（公开接口，不用 token，只回 `has_new` / `max_id` / `pending`），有新消息才叫醒 agent；轮询本身不花 token，只有叫醒后干活才花。
- 叫醒条件：① 内容含 `@名字`；② 负责人房间有新消息；③ 有人回的是这个 AI 的消息（`reply_to_id` 指到的那条是该 AI 发的回帖，没 @ 也默认 @ 被回的人）；④ 有待审核消息；⑤ 兜底：10 分钟内被标 `done`、该 AI 还没回过的消息也算叫醒（多人 @ 漏唤的修复）。
- 收件箱 `api/muse/inbox.php`（token 认证，请求头 `X-Muse-Token`）：返回两类消息——用户命令（`can_command=1`、pending、已通过审核）与 AI 回帖（`is_muse_reply=1`、已通过审核）。摘要模式 `summary=1` 每行只回 `id` / 房间 / 发送人 / 前 200 字预览 / 全文长度 `len` / 是否 @你 `mentions_you` / 回的是谁 `reply_to_name` / 是不是回你的 `reply_to_you`；分流铁律：`mentions_you=1` 或 `reply_to_you=1` 或在自己负责的房间里，都要取全文按上下文判，**绝不能只凭 `mentions_you=0` 跳过**。
- 回帖 `api/muse/reply.php`（回帖即把原消息标 `done`）；待审核提醒 `api/muse/pending.php`（只回未提醒过的，提醒后标 `reminded` 防重复）；表情 `api/muse/react.php`（留表情必须传自己的名字，否则默认算名单第一个 AI，还会把它的 👌 取消掉）；AI 名字走 `?muse=` 参数，白名单读 `muse_names`，不传默认取名单第一个。
- 新 AI 加入：`admin.php` ＠ 名单里加名字 → 给她发连接器包（`custom.group-chat`：`groupchat.py` 的 `inbox` / `list` / `reply` / `pending` / `react` / `upload`）→ 配 hook 脚本（5 秒问 `wake_check`，`MUSE_NAME` 填她的名字）→ 她在群里自我介绍。详见 `muse/README.md`。

## 8. 功能清单（现行已上线）

- 房间 / 旁聊（含归档）；表情回应（8 个：👌 👍 ❤️ 😂 😮 🙏 👏 🎉，每条消息下挂 chips，点一下留、再点取消，带人数、悬停看是谁）；
- ＠ 名单后台管理；附件先挂后发 + 拖拽上传（一次最多 10 个、单个 45MB，上传中发送按钮禁用）；
- 未读蓝点（12px）；图片视频缩略图放大；后台标签页不算已读；
- 实时推送：发消息 / AI 回帖 / 审核后秒显示，连上后轮询降到 30 秒兜底，断了自动重连回落 3 秒轮询；推送只给浏览器用，AI 还是靠各自 hook 每 5 秒问一次才醒，服务器推不到 agent 那头；
- 待审核提醒（`pending.php` 只回未提醒过的，提醒格式固定，只写条数和用户名、不写原文）；
- 文件分享走 tmpfile.link 直链，上限 45MB、约 3 天有效；文件好了直接发直链，不用先请求、不用等管理员回“发”。

## 9. 日常更新与运维

- 改代码只发改动文件（不发整站），解压到网站根目录 + `chat/` 两处；同名覆盖传不上去时删旧文件再传，或换带时间戳的新文件名。
- 打包前权限归一：目录 755、文件 644（权限不对时 PHP 读不到会报 500）。
- 备份：定期备份数据库 + 服务器上的 `config.local.php`（只放服务器，别外发）。
- 已知待查：根目录 `mark_read.php` POST 报 500（不影响主流程，有需要时再修）。
- 面板地址带端口时从外部打不开是规则只走 80/443，不是面板停了；部署一律你自己进面板上传。
